# CLAUDE.md

plotly.express is an R port of plotly.py's Plotly Express (the `px` module),
built on plotly.core (~/Documents/plotly.R.core), which provides graph objects,
validation, rendering and export. It was split out of plotly.core
(msummersgill/plotly.R.core#4).

# Local Resources

- plotly.core: ~/Documents/plotly.R.core (see its CLAUDE.md)
- plotly.py clone: ~/Documents/plotly.py (express: plotly/express/)

# Code

- R/express-core.R and R/express-figure.R port `_core.py`; R/express.R the `px_*()` functions (`_chart_types.py`); R/express-doc.R the shared argument docs (`_doc.py`); R/express-trendlines.R, R/express-imshow.R and R/express-data.R (the `px.data` datasets, in inst/extdata) the rest. R/crosstalk.R links px figures given a `crosstalk::SharedData`.
- Behaviour must match plotly.py: tests/test-express.R compares 72 cases with fixtures (tests/fixtures/) generated by tools/px_fixtures.py (needs plotly, pandas, numpy, statsmodels, pillow).
- plotly.core is imported whole (`@import plotly.core`). Its internals that px needs are exported under the internal help topic `plotly.core-extending`; never use `plotly.core:::` in package code (CRAN flags it). If px needs another plotly.core internal, export it there in plotly.core first.
- In px code, `args` is an environment (exact `$` matching, NULL values kept like Python's None). Never use `$` on user-supplied or template lists where partial matching could hit another name; use `[[`.
- Tabular data is handled with data.table (as.data.table(), setorderv(), set(), grouping with `by`), not data.frame/rbind/cbind/interaction()/per-group `%in%` scans. Split rows into groups once (row indices per group), not by scanning the data for each group. data.table functions that work by reference (setDT(), setorderv(), set()) must only touch tables the package created: setDT() on a list keeps the list's vectors, which may be the user's columns, so build tables from lists with as.data.table() (which copies).
- Inside data.table's `[`, only a lone variable name is evaluated in the calling scope; any expression in `i` sees column names first. Compute indices first (`o <- order(...); dt[o]`).
- Examples (roxygen and README) pipe the data in and refer to columns with formulas: `px_data_tips() |> px_bar(x = ~day, y = ~total_bill, color = ~sex)`. Multi-column arguments use `~c(a, b)`. Rows are filtered with data.table subsetting: `px_data_gapminder()[continent == "Oceania"] |> px_line(...)`.
